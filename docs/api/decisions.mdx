## 接口与鉴权

```text
POST https://emrank.tech/v1/decisions
```

`POST /v1/decision` 是相同接口的单数别名。使用主站“令牌管理”创建的 API 令牌，以 `Authorization: Bearer <API Key>` 传入。这是 System One 决策协议，不使用聊天接口的 `messages`。

## 请求字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `model` | 是 | [完整公开模型 ID](/guide/model-ids)，必须具有可用决策渠道 |
| `state` | 是 | 待判断的文本、JSON 对象或数组 |
| `questions` | 是 | 非空问题字典，每个问题有独立 ID |
| `images` | 否 | 仅在模型支持时使用内嵌 PNG/JPEG/WebP 图片 |

每个问题包含 `type`、`instructions` 和可选或必需的 `criteria`。`instructions` 可以是非空文本、对象或数组。

| type | 用途 | criteria |
| --- | --- | --- |
| `noul` | 判断成立的概率 | 可省略，或提供 `true` / `false` 描述 |
| `choice` | 从选项中分类 | 至少两个选项的字典，选项描述可以为 null |
| `score` | 对有序等级评分 | 至少两个等级的数组 |

## 调用示例

先在[模型广场](https://emrank.tech/models)确认模型可用。以下演示固定使用 TypeSafe 1.14.0；示例本身不代表该渠道当前已启用。

```bash
curl https://emrank.tech/v1/decisions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "typesafe/jev-1.14.0",
    "state": {"description": "一本书，封面有轻微划痕，内页完整"},
    "questions": {
      "damaged": {"type": "noul", "instructions": "商品本体是否损坏？"},
      "category": {
        "type": "choice", "instructions": "商品属于哪类？",
        "criteria": {"book": "书籍", "other": "其他"}
      },
      "severity": {
        "type": "score", "instructions": "外观损伤程度",
        "criteria": ["无损伤", "轻微损伤", "严重损伤"]
      }
    }
  }'
```

JavaScript 可用标准 `fetch`，无需专用 SDK：

```js
const response = await fetch("https://emrank.tech/v1/decisions", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.OPENAI_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "typesafe/jev-1.14.0",
    state: "商品包装有划痕，内部完好",
    questions: {
      damaged: { type: "noul", instructions: "商品本体是否损坏？" },
    },
  }),
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const result = await response.json();
console.log(result.answers.damaged.noul);
```

## 响应与用量

响应的 `answers` 按原问题 ID 返回答案：`noul` 为 0–1 的肯定概率；`choice` 返回选项以及概率、置信度；`score` 返回从 0 开始的加权等级，可能为小数，并包含概率和等级说明。不同模型的能力限制以实际配置为准。

`usage.input_tokens` 和 `usage.output_tokens` 仅在上游提供有效值时返回。**本站只按输入 Token 计费**，输出用量展示不代表扣费；详细规则见[计费说明](/guide/billing)。

## latest 与固定版本

| 请求 model | 上游选择 |
| --- | --- |
| `typesafe/jev` | 跟随官方 `jev-latest` |
| `typesafe/jev-1.14.0` | 固定 1.14.0 |
| `typesafe/jev-1.13.0` | 固定 1.13.0 |

截至 2026-10-15，按站点维护者确认的信息，latest 对应 1.14.0。需要可重复的版本选择时，请使用完整固定版本 ID。固定版本不会自动切换到 latest 或另一版本。

## 图片与错误排查

图片只支持内嵌 data URL 或 `{ "content_type": "image/png", "base64": "..." }`，不下载远程图片。TypeSafe 当前未声明图片支持。整个决策请求默认上限为 13 MiB，具体图片数量和大小还受模型能力限制；网关不会为适配渠道而丢弃图片或拆开问题。

- 401：检查本站 API 令牌，不要使用系统访问令牌或厂商 Key。
- 400：检查问题类型、criteria、扩展字段及图片能力。
- 模型不存在或无可用路由：核对完整模型 ID 和模型广场的可用状态。
- 429：查看请求频率及重试提示；重复发送失败请求仍可能计入 RPM。

排查时保留响应头 `X-Request-ID`，到主站“日志”查看请求模型、状态与用量。
