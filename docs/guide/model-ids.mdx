## model 必须完整匹配

从[模型广场](https://emrank.tech/models)复制模型 ID，或带 API 令牌调用 `GET https://emrank.tech/v1/models`。请求 `model` 必须保留完整命名空间、大小写和版本号；网关不会根据最后一段名称猜测模型。

例如 `Qwen/Qwen3-Embedding-8B` 与 `Qwen3-Embedding-8B` 是不同 ID。默认 ID 常为 `平台/模型`，但管理员可以显式配置其他公开 ID，因此**不要自行添加或删去平台前缀**。

## 公开 ID、渠道与上游名称

| 概念 | 用途 |
| --- | --- |
| 公开模型 ID | 用户请求中填写的 `model` |
| 渠道 | 网关调用上游时使用的连接、凭据和路由 |
| 上游模型名 | 网关实际发给该渠道厂商的代码，可与公开 ID 不同 |

同一公开模型可以显式关联多个渠道，由优先级和故障转移规则选择。请求中的平台名称不保证锁定某条渠道。

例如本站 `Qwen/Qwen3-Embedding-8B` 已合并讯飞和 Nebius 路由；即使通过带 `nebius/` 的重定向来源请求，仍按目标模型的全部路由选择，不会因此强制使用 Nebius。

## 重定向必须显式配置

管理员在“设置 → 模型重定向”配置后，来源 ID 才能指向目标公开模型。同类型才可重定向，不支持链式跳转或循环。未配置的旧名称不会自动兼容。

重定向按目标模型倍率计费，日志显示完整 `请求 ID → 目标 ID`。目标没有启用路由时，别名同样不可用。

## 固定版本与 latest

`typesafe/jev` 使用官方 `jev-latest`；`typesafe/jev-1.14.0` 和 `typesafe/jev-1.13.0` 分别固定对应版本。latest 将来可能升级；需要指定版本时应直接填写完整固定版本 ID。

## 排查模型不可用

1. 确认请求的是正确的接口：向量、重排序和决策模型不可互换。
2. 核对完整 ID，包括大小写、前缀和版本。
3. 在模型广场确认可用状态。模型存在但渠道停用，不代表可以调用。
4. 如果使用旧 ID，确认管理员是否配置了对应重定向。
5. 保留 `X-Request-ID`，在日志中核对请求模型和错误类别。
