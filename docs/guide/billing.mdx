## 如何扣费

计费启用时，本站只按成功请求的**输入 Token**扣除账户额度，输出 Token 不参与扣费：

```text
扣除额度 = floor(输入 Token × 模型倍率 × 用户等级倍率 × RPM 倍率)
```

`floor` 表示最后一次向下取整。倍率在请求准入时确定，同一请求内部换渠道、重试或故障转移不重新取价，也不会重复扣款。批量分片先汇总完整输入用量，再做一次取整。

例如输入 1,000 Token，模型倍率 3、等级倍率 1.5、RPM 倍率 1，则扣除 `4,500 Token`，即 `0.0045 M Token`。这些倍率仅用于演示，实际以站点配置和账单为准。

模型倍率查看[模型广场](https://emrank.tech/models)；账户余额、等级与当前 RPM 信息查看[个人中心](https://emrank.tech/account)。多个上游共同服务同一公开模型时，使用该公开模型的统一倍率。

## 单位与美元价格

本站余额使用额度单位：**1 M Token = 1,000,000 Token**。余额扣除值包含倍率，不一定等于上游输入 Token 数量；厂商美元单价不直接等于本站倍率。

如果厂商只对输入按 `$0.042 / 百万 Token` 收费，且没有其他费用，`$5` 对应约 `119,047,619` 个输入 Token。这是上游成本预算换算，不代表本站账户充值或兑换比例。

## 成功、失败与未知用量

- 只有完整成功且输入用量可计量的请求才自动计费。失败请求不会自动按成功结果扣费，但已认证推理 POST（包括无效或失败请求）可能占用 RPM。
- 上游提供有效输入用量时优先采用，明确的 0 也是有效值。
- 部分适配器明确启用了输入用量估算兜底；上游缺失用量时，按配置的估算结果计费，日志和账单保留估算来源。
- 未启用估算且缺失输入用量时，保持未知，不按 0 展示，也不自动按成功结果扣款。批量中任何分片缺失用量时，不把部分已知用量当完整用量扣费。

网关不会因删除或关闭技术日志而删除账单，也不会因后续修改倍率重算历史账单。

## 余额、RPM 与密钥额度

计费启用时，请求进入需要账户余额大于 0；已获准请求结算后可能使余额变为负数。个人 API 令牌的额度与账户余额分别受限，创建新令牌不会增加账户余额。

RPM 按用户统计，该用户的多个 API 令牌、协议入口共同计数。更换令牌不能重置限速；站点可配置不同 RPM 档位倍率和硬上限。

渠道管理中的“每日 / 累计输入 Token 上限”是**每个上游密钥独立**的调度配额，渠道默认值作用于各密钥；它不等于所有密钥合计共享一个预算。该配额只统计输入 Token。用量尚未核对时保留未知记录，继续累计后续已知用量，之后补充核对值；在途请求及未知用量可能使实际消耗短时超过设置值，不能当作厂商美元余额的绝对硬上限。

## 查看账单

进入主站[日志](https://emrank.tech/requests)，查询自己的请求、扣费及额度变动。请求按公共模型的倍率结算，多渠道切换不改变倍率、不重复扣费。旧重定向记录仅保留历史展示。技术日志过期后，财务记录仍可保留。
